# Smart-Browser 0.4.0

The first release with a browser in it.
It browses like Chrome and saves like the extension: `⌘⇧B` opens a save sheet over the page, and the tags you give it go straight into your library.

## Upgrading from 0.3.0

No migration: the database stays at revision `0003`.

1. **Install the browser's dependencies**, once, from the repo root:

   ```sh
   make browser-install
   ```

2. **Run it:**

   ```sh
   make browser-dev
   ```

   The first time it loads a page on the internet, the Mac's outbound firewall asks whether Electron may connect; a page that never loads is an unanswered prompt.
3. **Connect it to your API**: Settings (`⌘,`), then the API's address and a token, the token half of an `API_TOKENS` entry.
   Test the connection, then save.
   The token is kept in the Keychain and never shown again.
4. **Reload the extension** (`chrome://extensions`): it no longer refuses tags over 32 characters, and it shows the server's own reason when a save is refused.

## Highlights

**A browser.**
Tabs with their titles and favicons, dragged to reorder and reopened on the next launch.
An omnibox that visits an address or searches, with DuckDuckGo by default and Google or Bing in Settings.
Chrome's keyboard shortcuts, and a link that tries to open a new window opens a tab beside its page instead.

**Saving is part of it.**
`⌘⇧B` opens the save sheet over the page: whether the page is already saved and with which tags, suggestions from your own tags ranked by how often you use them, `Tab` to take one, `Enter` to save.
`⌘⇧S` saves without asking.
A button in the toolbar says whether the page you are on is saved, and with how many tags.
The title saved is the one the tab showed, which a crawler behind a login would never see.

**It keeps pages to themselves.**
Web pages run sandboxed in their own session, cannot reach the browser's own interface, and are refused camera, microphone, location and notifications.
The browser's own interface has no network access at all, and your API token never leaves the part of the browser that talks to the API.
At startup it checks that the API speaks the same contract, and says why saving is off if not.

**Tag names mean the same thing everywhere.**
A tag can no longer contain a comma, which `?tags=` would split, or whitespace, which every client splits typed tags on; anything else is allowed, `c++` and `ci/cd` included, with no length limit.
A misspelling registered as an alias now finds, removes and keeps the tag it stands for on every path, not only when saving.
Editing a page's tags by an alias no longer turns an AI suggestion into your own choice.

## Fixed

- **A tag containing `/` could be saved and never removed.**
- **The extension refused tags over 32 characters**, a limit the server dropped in 0.2.0.
- **A version bump left `package-lock.json` describing the previous release**; the release tooling now moves every entry.

## Under the hood

- The browser is TypeScript, Svelte, Vite and esbuild, and its types for the API are generated from the API's contract, so a contract change that would break it fails `make check`.
- `make test-browser-e2e` drives the built browser with Playwright against the real API on the test database and a local site, and writes every layer of the window to snapshots, so its screens are looked at, not only asserted on.
  CI runs it on Linux, sandboxed, with a real keyring.
- The decisions are ADRs 0014 (tag names) and 0015 (the browser) in `doc/decisions/`.

## Known issues

- The browser has no history, downloads beyond Electron's defaults, or offline save queue yet, and is not packaged: it runs from the repo.
- PDFs and other non-HTML pages are fetched but not read.
