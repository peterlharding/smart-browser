# Release notes

One file per release, named `v<version>.md`, written for a reader who wants to know what
changed and why rather than which commits landed.

Structure:

- A short intro — one or two sentences on what this release is for.
- **Highlights** — the changes worth knowing about, in plain language.
- **Fixed** — bugs closed, if any.
- **Under the hood** — internal work with no user-visible effect.

`CHANGELOG.md` is the terse, complete record; these are the readable version. Both are
maintained by hand.
