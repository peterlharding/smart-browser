# Smart-Browser 0.5.0

The browser keeps its own history, and the bookmarks API hears only about the pages you choose to keep.

## Upgrading from 0.4.0

No migration: the database stays at revision `0003`, and the API contract is unchanged.

1. **Rebuild and run the browser:**

   ```sh
   make browser-dev
   ```

   History starts empty: 0.4.0 kept none.
   It is kept in `history.db` in the browser's profile, beside `settings.json`.
2. **Restart `make api-dev`** if you run it: it now listens on `API_HOST` and `API_PORT` from `.env`, and the browser's Settings should name the same address.

## Highlights

**Browsing sends nothing to the API.**
0.4.0 looked up every page you loaded, and every tab you switched to, to fill the save button, and asked the API's health at every launch.
Now the API is contacted only when you act: opening the save sheet (`⌘⇧B`), a quick save (`⌘⇧S`), removing a tag, or testing the connection in Settings.
The save button shows what this browser knows: a page saved or looked up here shows as saved with its tags, and any other page shows a plain save button.
A page saved from the extension is recognised the first time you open the sheet on it.

**History, kept on your machine.**
Every page you visit is kept for 90 days in the browser's profile, and nowhere else.
The History menu goes further than Chrome's:

- Show Full History (`⌘Y`) and Search History (`⌥⌘Y`).
- History for This Site, for the page you are on.
- Reopen Closed Tab (`⇧⌘T`), and Recently Closed, the last ten tabs, each reopened where it was with its back and forward history.
- The pages you visited last, with their favicons.
- A submenu for each earlier day this week, as Safari has.
- Delete Browsing Data (`⇧⌘⌫`).

**A history page like Chrome's.**
`smart://history/` lists your visits by day, with the time, favicon, title and site of each.
Search matches the start of any word in a title or address.
Each row's menu offers More from this site and Delete from history, and ticked rows are deleted together.
Delete browsing data clears history over the last hour, day, week, four weeks or all time, and can also clear cookies and cached files.
A page opened from history opens in that tab, and Back returns to the history page; `⌘`-click opens it in a new tab.
The page reopens on the next launch showing what it showed.

## Fixed

- **A page with the same favicon as the page before it showed none**, in the tab strip since 0.4.0, because Chromium only announces an icon when it changes.
- **A page opened into a new tab from the menu left the address bar editing an empty address** over the page.

## Under the hood

- History is SQLite through Node's built-in `node:sqlite`, which Electron ships, so there is no native module to rebuild; search is SQLite's full-text search.
- The history page runs in the browser's own session, with a bridge that offers history and nothing else; web pages cannot load it.
- The end-to-end suite proves the traffic claim with a recording proxy in front of the API, launch included.
- The decision is ADR 0016 in `doc/decisions/`.

## Known issues

- Cookies and cached files are cleared for all time whatever range is chosen: Electron clears them by site, not by date. The dialog says so.
- The browser has no downloads beyond Electron's defaults or offline save queue yet, and is not packaged: it runs from the repo.
- PDFs and other non-HTML pages are fetched but not read.
