# Smart-Browser 0.3.0

The release that finishes M3: saved pages are now fetched, read and turned into vectors.
Those vectors are what tag suggestions (M4) and "pages like this one" (M6) will compare, so this is the last piece of groundwork before either.

## Upgrading from 0.2.1

No migration: the database stays at revision `0003`.

1. **Run the embedding pass** alongside the API and the crawl worker:

   ```sh
   make embed
   ```

   The first run downloads the model once, 64 MB, into `~/.cache/smart-browser/models`.
   `make crawl-status` now says how many pages are embedded.
2. **Check `EMBEDDING_MODEL`** if your `.env` sets it.
   The example `.env` used to say `bge-small-en-v1.5`; it must now be `BAAI/bge-small-en-v1.5`, as `fastembed` names it, or be left out for that default.
   `make embed` refuses the old name with a message saying exactly this.
3. **Remove `EMBEDDING_BACKEND`, `EMBEDDING_DIM` and `OLLAMA_BASE_URL`** from your `.env` if they are there.
   Nothing ever read them, and they are ignored now.

## Highlights

**Every crawled page gets a vector.**
`make embed` turns each page's title, description and the opening of its text into a 384-dimension vector with `bge-small-en-v1.5`, run locally.
In a test with three saved articles, the two about Postgres scored 0.75 against each other and 0.46 against the one about bread.

**It is small and fast to start.**
It runs the model through `fastembed`, which was measured against the PyTorch-based `sentence-transformers`: the same vectors, a fifth of the install size, and a thirtieth of the load time.
It embeds about twelve full pages a second.

**Changing the model re-embeds everything, with no migration.**
Each vector records the model and the recipe that made it, and anything made by a different one is simply done again.
That is what will let M4's benchmark against the hand-tagged bookmarks try another model or another way of choosing the text.

**It runs apart from the crawl worker**, so a problem with the model never stops pages being fetched, and two embedders can run at once without doing the same page twice.

## Fixed

- **An `EMBEDDING_MODEL` copied from the old example `.env` failed with an error that named neither the setting nor the fix.**

## Under the hood

- The default test suite never downloads the model: the embedder takes it as a parameter and a fake stands in.
  `make test-model` runs the real one, locally when you ask and in CI on every push, with the model cached.
- A Postgres test shows a nearest-neighbour query using the vector index, and another that two embedders take different pages.
- `RELEASING.md` now tags a release only after CI has passed on its commit, the lesson of 0.2.0.
- The decision and its measurements are ADR 0013 in `doc/decisions/`.

## Known issues

Unchanged from 0.2.1:

- The extension still refuses tags longer than 32 characters, although the server no longer limits them.
- Tag names are not validated on the server, so a tag containing a comma can be saved and never filtered on.
- Filtering by tag does not follow tag aliases.
- PDFs and other non-HTML pages are fetched but not read.
