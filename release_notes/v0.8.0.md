# Smart-Browser 0.8.0

The browser keeps itself up to date, without interrupting you.

## Installing

Download `Smart-Browser-0.8.0-arm64.dmg` below, open it, and drag Smart-Browser to Applications, replacing an earlier copy.
Signed and notarized, Apple silicon only.

**This one still has to be installed by hand.**
0.7.0 had no update code to run, so it cannot fetch this release itself.
From here on it is automatic: the next release arrives by itself.

Your history, saved pages and settings are kept; nothing needs doing after the upgrade.

## Upgrading from 0.7.0

No migration: the database stays at revision `0003`, and the API contract is unchanged.

## Highlights

**It updates itself.**
At launch, and every six hours after, the browser asks whether a newer release exists, and downloads it in the background.
Nothing interrupts you: no dialog, no progress bar over the page you are reading.

When an update is ready it says so in two quiet places:

- the first item of the **Smart-Browser** menu becomes **Restart to Update to `<version>`**;
- the settings button in the toolbar carries a small blue dot.

Either one restarts into the new version.
Ignore both and the update is applied the next time you open the browser anyway, which is how macOS updates of this kind work.

**You can ask, and you can decline.**
**Check for Updates Now** sits in the Smart-Browser menu and works whenever you want it.
Settings has **Check for updates automatically**, on by default; turning it off stops the checking immediately, and the manual check still works.

**It says what it sends.**
A check tells `update.electronjs.org` this version, that it is macOS, and which processor — nothing about the pages you visit, and nothing about your library.
That service is Electron's, separate from your bookmarks API, which still hears only about pages you choose to keep.

## Known issues

- **Auto-update is unproven until this release is superseded.**
  Nothing automated can show that the app is really replaced: it takes two signed, notarized releases and the live service.
  0.8.0 is the first release with the update code, so the first genuine test of it is the next one.
  `RELEASING.md` has the recipe, and the result will be recorded in that release's notes.
- A failed check is silent by design; if you suspect one, run the app from a terminal and look for `[updates]` lines.
- Apple silicon only, and the icon is still a placeholder.
- No downloads beyond Electron's defaults, and signing in is still an API token rather than OAuth.

## Under the hood

- Electron's own `autoUpdater` against `update.electronjs.org`, rather than the usual wrapper around it, which always checks the moment it is called and so could not express "no check while the switch is off" or "a manual check that still works then".
- No test ever reaches the service: a build run from the repo cannot update itself, a packaged one under test is switched off, and both end-to-end suites assert the app has no update feed set, which is proof rather than assumption.
- The decision is ADR 0019 in `doc/decisions/`, sketched first in `doc/m5-auto-update.md`.
