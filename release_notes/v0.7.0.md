# Smart-Browser 0.7.0

The first release you can install: a signed, notarized `Smart-Browser.app`, in a disk image, rather than something run from a terminal.

## Installing

Download `Smart-Browser-0.7.0-arm64.dmg` below, open it, and drag Smart-Browser to Applications.
It is signed with a Developer ID certificate and notarized by Apple, so macOS opens it without a warning.
Apple silicon only.

On first launch:

1. Open Settings (`⌘,`) and enter your API's address and a token, the token half of an `API_TOKENS` entry.
   The packaged app keeps its token in its own Keychain entry, so it asks once even if you used a build from the repo before.
2. History starts empty.
   The app browses in `~/Library/Application Support/Smart-Browser`; a build run from the repo now uses `Smart-Browser Dev` instead, so experiments stay out of your way.

There is no auto-update yet: it is the next piece of work, and this release carries the zip it will use.

## Upgrading from 0.6.0

No migration: the database stays at revision `0003`, and the API contract is unchanged.
Nothing else about the browser changed in this release; if you run it from the repo, `make browser-dev` now uses the `Smart-Browser Dev` profile, which starts empty.

## Highlights

**An app.**
`Smart-Browser.app` carries its own icon, its own name in the menu bar and the Dock, and its own identity for macOS.
That identity is what the Keychain uses to keep your API token, and what the firewall remembers when it asks whether the browser may reach the network, so neither asks again on every upgrade.

**Signed and notarized.**
Signed with a Developer ID certificate under Apple's hardened runtime, with one permission beyond the default: the ability to run compiled JavaScript, which every browser engine needs.
Nothing for the camera, microphone or location, which the browser refuses to pages anyway.
Apple's notarization service has checked it, and the result is stapled to both the app and the disk image, so it opens even offline.

**Built with Electron's own tools**, from a hundred-line script beside the existing build, with no packaging framework in between.
Packaging takes about three seconds, because the app is the built code and nothing else: every dependency is already bundled, and the database engine comes with Electron.

## Under the hood

- `make browser-package` builds the app signed ad hoc, to try locally; `make browser-release` signs, notarizes and staples it and makes the disk image and the zip.
  `RELEASING.md` describes the one-time notarization setup.
- `make test-browser-e2e-packaged` runs the whole end-to-end suite against the packaged app, not just the built code.
  It passed against this release's notarized app.
- CI packages the app on a macOS runner and starts it, so packaging cannot break unnoticed.
- The decision is ADR 0018 in `doc/decisions/`, sketched first in `doc/m5-packaging.md`.

## Known issues

- No auto-update yet: a new version means downloading the next disk image.
- Apple silicon only; there is no Intel build.
- The icon is a placeholder.
- The browser has no downloads beyond Electron's defaults, and signing in still means an API token rather than OAuth.
