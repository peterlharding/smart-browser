## Tag vocabulary drift

Four case/punctuation-equivalent clusters: `linux`/`linux`, `webdev`/`web-dev`,
`fontawesome`/`font-awesome`, and `c`/`c#`/`c++` (that last one is a false positive of
normalisation, not a real duplicate — punctuation is semantic there).

32 near-duplicate pairs at >0.88 similarity, including:

```text

moorcycles/motorcycles       camping/campling             imageing/imaging
fontaewsome/fontawesome      fontawesome/fontawesomw      multiimedia/multimedia
apollo/apolo                 3dprinter/3dprinters         article/articles
```

Some pairs in that list are legitimately distinct (`html`/`html5`, `angular`/`angular2`,
`auth`/`oauth`, `books`/`ebooks`, `network`/`networks`) and must not be merged blindly.
The list is a review queue, not a migration script.

## Findings

### 1. The multi-category feature already exists and is unused

`bookmark_tag` is a proper join table. The average tagged bookmark carries 1.44 tags and 1,148
of 1,817 carry exactly one. Tagging isn't blocked by the data model — it's blocked by tagging
happening *later*, by hand, in a web form you have to navigate to. Moving tagging to the moment
of saving is the browser's job.

### 2. 80.8% untagged is the real problem

A tag-native browser over a corpus where four of five items have no tags is a browser over an
empty index. AI categorization is not a feature to add at the end; it is what makes the corpus
usable, and it needs to run as a backfill over 7,655 existing bookmarks before the UI is worth
looking at.

### 3. No constraints

Three primary keys. No foreign keys, no unique index on URL, and **no index on
`bookmark_tag(tag_fk)`** — the lookup the entire product depends on. IDs are allocated with
`SELECT MAX(id)+1` in application code, which races under any concurrency. Acceptable for a
single-user 2015 tool; not for a browser that writes on every save.

### 4. `/xyzzy` is unauthenticated

Every other route carries `Depends(get_current_username)`. The one route that *writes* does not.
It is public on `bookmarks.performiq.com`.

### 5. The tag suggester silently returns nothing

`suggest_tags_from_content()` (`app/src/app/main.py:1091`) asks the model for tags in free form,
then parses with:

```python
tags = [line.split('. ', 1)[1].strip() for line in content.splitlines() if '. ' in line]
```

This expects a numbered list the prompt never requests. Most calls yield `[]`. The `corrections`
dict below it is a hand-maintained band-aid for the same tag-alias problem this audit measures
32 instances of.

### 6. `host` is not a domain

`host` holds the *poster's* IP or hostname (`AASDev` on 8,661 rows), yet a
`/bookmarks/list-by-domain` route exists. That route cannot be doing what its name says.

### 7. Smaller items

- `extract_page_text()` fetches with `verify=False` and suppresses urllib3 warnings.
- `Bookmark.Init()` references undefined names `bookmark_url` / `bookmark_title` — it would
  `NameError` if called. Nothing calls it.
- `models/bookmark.py` declares `title` as `String(64)`; the database column is `varchar(256)`.
- `Bookmark.Add()` and `Bookmark.Insert()` are `pass`.
